# 背屏初始化操作手册

首次打开 App，点击「自动设置背屏」或「手动设置背屏」。日后入口：**设置 → 背屏设置与使用指南**。同一弹窗顶部可切换两页；「遇到问题？」展开更多说明与恢复操作。

## 自动设置：Shizuku（推荐，无需电脑）

1. 安装 [官方 Shizuku](https://shizuku.rikka.app/zh-hans/download/)，按其中的「通过无线调试启动」指引配对并启动。手机需连接 Wi-Fi，并开启开发者选项中的无线调试；完整步骤见 [官方启动指南](https://shizuku.rikka.app/zh-hans/guide/setup/)。本项目最低 Android 12，满足无线启动所需的 Android 11 以上要求。
2. 回到 App → 自动设置。点击「授权并自动设置」，在 Shizuku 提示中允许每日背屏。已授权时，按钮为「自动设置背屏」。
3. App 自动准备、校验并安装模板，随后打开系统背屏页面。首次点击「应用」；已添加过的模板直接从系统列表选用「每日背屏」。
4. 唤醒背屏，回到 App 检测连接。文件安装成功与背屏已读取模板是两个独立状态。

Shizuku 使用官方 UserService API，仅在这次安装期间运行辅助进程；完成、失败或超时后释放连接。无需 Root，无需输入命令。手机重启后，若需要再次安装模板，须先重新启动 Shizuku；**已经应用的模板在日常换图时不依赖 Shizuku 常驻**。

授权可在 Shizuku → 已授权应用中管理。未安装、未启动、版本过旧（需要 v13+）、拒绝授权、连接中断都会在引导中给出下一步。返回引导时 App 会主动重新获取连接，以兼容先安装 App、后启动 Shizuku 的情况。如果系统仍拦截连接，可从最近任务中划掉每日背屏后重新打开。

## 自动设置：电脑 ADB（备用）

在自动设置页展开「使用电脑 ADB 设置」，不需要安装 Shizuku。

1. 在电脑安装 [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools)。手机开启开发者选项中的 USB 调试，用数据线连接，并允许这台电脑调试。电脑执行 adb devices，设备应显示 device；unauthorized 表示需要在手机上授权。
2. 打开 App 的初始化弹窗，等待安装文件准备完成，复制按钮变为可用。点击「复制安装命令」或「分享命令到电脑」，在电脑终端执行。保持手机解锁。
3. 命令自动校验文件、创建属于本次 App 安装的独立目录，并在手机打开系统背屏预览。点击系统的「应用」。
4. 唤醒背屏，返回 App 点击「检测连接」。出现「已连接」，说明背屏服务已读取本安装的模板。详细历史读取记录可在「遇到问题？」中查看。

无需先在系统设置里创建占位壁纸，也无需选择文件夹。命令由当前手机生成，不要复制其他设备的路径。之后换图片和视频无需电脑；已登记过的模板会直接打开系统背屏列表，选用“每日背屏”即可，避免重复添加。换机或卸载重装后重新初始化；需重新应用更新后的模板时，先在系统列表移除旧“每日背屏”，再回 App 打开预览。

Windows PowerShell 若在 Platform Tools 目录中运行，可把命令开头的 adb 写成 .\adb.exe。多设备连接时，在 adb 后加入 -s 目标序列号。

## 手动设置（自动入口不兼容时）

手动页保留电脑 ADB 的查询、备份替换和恢复流程。Shizuku 按钮用于自动创建独立模板；它不会自动选择并覆盖系统中已有的其他壁纸。

### 1. 创建专用占位壁纸

进入系统背屏设置 → 背屏个性化 → AI 壁纸，用已有图片创建并保存一个专用壁纸。菜单名称可能随系统版本变化。这里不需要发起付费 AI 生图。记录名称和预览，避免替换其他壁纸。

先打开 App 初始化弹窗准备文件，再切换「手动设置」。若自动预览接口不可用，只要基本背屏服务兼容，仍可以准备文件。

### 2. 确认目录

在手动页复制「复制查询命令」并在电脑执行。必要时在创建壁纸前后各查一次，对比新增目录。候选通常位于当前 Android 用户存储根目录下：

~~~text
Android/data/com.android.thememanager/files/MIUI/.ai_wallpaper/maml/<实际壁纸 ID>/
~~~

有效目录至少包含 rearscreen 和 description.xml。出现多个目录时结合预览图确认，不按修改时间自动选择。若没有目录，说明这次操作尚未生成兼容模板；需要在系统中完成创建 / 保存步骤。

### 3. 备份并替换

在 App 输入框粘贴确认过的目录名（最后一段，不含斜杠），点击「复制替换命令」并执行。

脚本先把原始 rearscreen 复制到临时备份，校验后保存为 rearscreen.reardaily-original，然后校验新模板并替换。重复执行保留第一次备份。description.xml 和其他壁纸不被替换。

若使用授权文件工具：新模板在 App 外部文件目录的 files/rear-setup/rearscreen；备份所选目录原文件后，用它替换同名文件。请保留原目录的其他文件。不要解压新 rearscreen，它本身就是系统需要的 ZIP 包。

### 4. 重新应用

退出旧预览，回到系统设置，重新选中刚才的占位壁纸并点击「应用」。唤醒背屏，再回 App 检测。手动替换完成后，通过原占位壁纸应用，不使用自动页的独立模板预览。

### 恢复

保留同一目录名，展开「遇到问题？」，点击「复制恢复命令」。脚本校验并恢复 rearscreen.reardaily-original，随后在系统中重新应用该壁纸。App 的素材缓存和收藏不受影响。

自动方式使用独立的「每日背屏」资源。停用时直接在系统中切换回其他背屏壁纸，也可在系统背屏列表移除「每日背屏」。升级安装保留的 *.backup.* 目录不自动删除。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| Shizuku 未连接 | 先在 Shizuku 中启动；若显示运行仍未连接，从最近任务划掉每日背屏再打开 |
| 授权被拒绝 | Shizuku → 已授权应用中允许每日背屏，再回到自动设置 |
| 安装连接中断或超时 | 重新启动 Shizuku 后重试；脚本支持重复执行，保留现有模板及备份 |
| adb 找不到设备 | 检查数据线、USB 调试和授权，执行 adb devices |
| 未检测到兼容服务 | 当前设备或 ROM 不支持本项目的背屏模板 |
| Permission denied | 确认使用已授权的 Shizuku 或电脑 adb shell；若 ROM 仍拒绝，需要兼容的授权文件工具 |
| 自动预览未兼容 | 系统内部接口可能改变，切换手动页；不要把预览失败当作已应用 |
| 模板已安装但无读取记录 | 在系统预览点应用并唤醒背屏，然后重新检测 |
| 素材已缓存但背屏没变化 | 确认正在使用每日背屏模板或正确的手动占位壁纸 |
| 提示另一个安装正在运行 | 等待当前操作结束；意外断电后确认没有安装运行，再通过文件工具检查并移除 files/rear-setup/.install-lock 空目录，然后重新准备 |
| 发现未完成暂存 / 备份 | 检查该目录与保留文件，确认原始壁纸可恢复后处理；脚本会停止而不覆盖不明状态 |
| 最近读取时间较早 | 这是历史读取记录，唤醒背屏后再次检测；不能代表此刻一定在显示 |

普通 App 的存储权限不能直接写其他 App 的 Android/data 目录，因此首次需要 Shizuku、电脑 ADB 或授权文件工具。[Android 官方存储限制说明](https://developer.android.com/about/versions/11/privacy/storage)。无需 Root，完成模板应用后无需保持授权服务常驻。

## 适配边界

本机 Android 17 + 官方 Shizuku 13.6.0 测试中，Shizuku 的应用管理列表为空，但 App 内授权弹窗、模板安装和连接恢复可用；管理列表问题属于上游版本兼容范围。不能仅凭列表数量判断本 App 是否已获授权。

目前自动预览适配小米主题管理器 11.5.3.1 的本地自建资源入口。安装时只加载设备上已安装的系统资源模型，不附带厂商代码。系统包名、组件名和 MAML 格式属于 ROM 适配部分；不同厂商、无背屏设备以及未来更改接口的系统需要新增适配，不承诺跨所有 Android 通用。
